# Hub build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the family's front door: a scroll-story home page, a cross-program page for every hospital with a
factor-level what-if, one shell (family bar, program tabs, short footer) on every page with the HACRP site moved into
it, coming-soon pages and an interim Readmissions page.

**Architecture:** Everything renders through the existing page build (`pipeline/site/`), shell (`web/render/layout.js`)
and the hub generator (`hub/pages.js`). Build-time data comes from the emitted FY2026 dollar estimates, the hospital
master and the pinned Thirty Day Readmissions file; the browser gets one hashed JSON asset of every hospital and draws
the story and the peer charts on canvas (and small SVG strips) from it. Pages carry their key numbers as server-rendered
text, so they read without scripts.

**Tech Stack:** Node 22+ ES modules, `node:test`, esbuild bundles (ES2020), Canvas 2D, inline SVG, d3-geo and
topojson-client at build time only (already dependencies), Playwright + axe-core for the browser checks.

**Spec:** the approved design for the hub home page and the cross-program hospital page (owner-approved 2026-10-27;
private planning repo). Its mockups of record are the reference for look, motion and behavior; port those, not their
code. This plan restates every requirement it relies on, so the spec need not be opened to build from it.

## The design in brief (restated from the spec)

- **Audience:** hospital quality directors and finance analysts who live in CMS spreadsheets and distrust a number
  that looks wrong; second, a curious first-timer. **Feel:** a serious, precise instrument that feels alive; useful in
  the first second; the data is the visual; motion only where it explains. Aim for breathtaking, never cute or busy.
- **Home:** a sticky chart beside step text. Each step changes one thing and moves the same 2,971 marks (one per
  hospital with an estimate); the chart never swaps for another. Steps: 0 Scale (one bar: estimated FY2026 Medicare
  inpatient pay; the ~0.67% the three programs move magnified ×100, split into "not paid" and "moved between hospitals
  as bonuses"), 1 Start at $0 (the dots pour out of the bar into one crowd at $0), 2–4 the gates (Readmissions, then
  hospital-acquired conditions, then value-based purchasing; each gate moves the hospitals it touches), 5 Net result,
  6 On the map (dots fly to their places), 7 By state (states fill on a diverging scale by state total = net $ ÷
  estimated Medicare inpatient pay; dots dim but stay; hover/focus/tap gives a one-line readout; Maryland hatched "Not
  in these programs"), 8 Find yours (a hospital ringed in its peer group and in all hospitals at once; peer toggle
  same state / same size / same teaching; a summary card links to its hospital page). Step text starts faded and darkens
  into place; a labeled, clickable rail on the left; search always reachable; a searched hospital is ringed through every
  step. Phones: step text above, chart pinned in the lower ~56% of the screen.
- **Piles stay dots:** no pile renders as a solid bar; every hospital is a visibly separate dot at 1440 and at 390. Big
  piles carry a count label ("147 hospitals at exactly −1%"). A dot histogram whose dot size shrinks until the tallest
  column fits.
- **Masthead:** "Paid & Penalized" across the full content width on one line (stacked on phones), the tagline-and-byline
  strip between rules, a heavy break rule; the story starts below it. On scroll the wordmark visibly travels (shrinks,
  sweeps left, rises) and docks into the header as the one-line wordmark. Reduced motion: no animation.
- **Below the story:** the program directory (live programs with a real figure and a small chart each; coming programs
  as quiet slips), a brief "how the numbers are estimated" linking to Methods, then "Your turn: what should I build
  next" in a dashed box. No "who builds this" section.
- **Hospital page `/hospital/<ccn>/`:** left, the red-bordered record card (hospital, location, type; no peer-group
  field), the net estimate across the programs with its stamp and a common-fiscal-year note (no ± band at launch;
  leave room for it), each program's dollars as rows adding to a net row, each with its peer-median tick, then a bold
  "What if? Adjust any program" button. Right, the peer swarm (this hospital ringed in its peer group, all hospitals
  underneath) under a headline sentence that states the comparison and updates during a what-if. A sticky peer toggle
  drives the whole page and moves the same dots. Program rows: one strip per program on one scale, a dashed thread
  through the hospital's position in each, an empty row for the next program, a net row. What-if: draggable capsule
  handles with arrows and a resize cursor, a first-view "drag me ↔" hint, factor fields with −/+ steppers, "match the
  group median"; once anything changes the top bar becomes a dashed "Hypothetical" banner with "Reset to actual", the
  stamp reads "What if", the actual figures stay as a ghost; keyboard arrows, shift for bigger steps, Esc resets. It
  adjusts each program's payment factor directly (HACRP: cut / no cut); measure-level what-ifs stay on each program's
  own pages, which the rows link to. An alphabetical peer table.
- **Shell (nav A):** family bar (one-line wordmark, "Public Medicare data, made visible." beside it in a smaller face,
  hidden on narrow screens; search top right over hospitals and states; a small icon-only light/dark toggle); a slim
  row of ledger-style program tabs under it on every page, current program marked, coming programs dashed (they open
  a coming-soon page), sideways scroll when they outgrow the row; switching programs keeps the current hospital. Program
  pages: the numbered section menu sticks under the tabs and marks the current part (total sticky height modest, about
  128px at 390). Phones: a compact "P&P" mark, the followed hospital's chip (name, net, ×) in the header row, search as
  an icon that opens a full row, the theme toggle moves to the footer, every tap target ≥ 44px. Footer: one numbered
  form row (programs; Methods, About, Corrections, Accessibility, Privacy, Terms; data as of; feedback form), then one
  signature line: "Built by Dalton Haslam, MD, MBA" · "Built with Claude Code" · not affiliated with CMS, plus the two
  lines approved on 2026-10-25 ("Nothing here is medical, legal or financial advice. Terms of use" and the content
  license). No email addresses, no turnaround promises.
- **Common fiscal year:** FY2026 for the net, with a visible note that each program's own pages may show a newer
  year. Net as a share of pay = net dollars ÷ estimated Medicare inpatient pay, never a sum of program percentages.
- **HVBP's $0 rows:** use `vbpListed`; an unlisted hospital reads "Not in this program", never "$0".
- **Which hospitals get a page and appear in search:** every hospital in the dollar file (3,055): the 2,971 with a net
  estimate, plus Maryland (all-payer model: "Not in these programs") and hospitals with no estimate ("No estimate" and
  the reason), which get the record card, the reason and links to the program pages they have, and no swarm position.
- **Readmissions until Thirty Day Readmissions folds in:** the Readmissions tab opens a slim page here (the program
  masthead, the followed hospital's figures from the pinned `hrrp.json`, and a clear "Full explorer on Thirty Day
  Readmissions" link).
- **Example hospital:** a page that opens on an example uses `EXAMPLE_CCN` (Task 2), never another default.

## Review Focus

1. **A `?h=` value that is malformed, lowercase, unknown, repeated or markup** (`?h=<img src=x>`, `?h=99`, `?h=abc123`
   twice): the shell ignores what it can't match (no chip, no rewrite, no error), never inserts markup, and accepts a
   lowercase CCN. Task 5 tests it.
2. **A shared what-if link with junk** (`#whatif&hrrp=2&hrrp=0.99&hvbp=abc&hac=7`, or a value for a program the
   hospital is not in): every bad part is dropped, the rest loads, and the "Reader-made scenario" banner shows only for
   a valid changed scenario. Task 9 tests it.
3. **A hospital without an estimate, or without a teaching status or bed count:** its page is the variant (Maryland:
   "Not in these programs"; others: "No estimate" and the reason), the missing peer toggles are disabled with the
   reason, and nothing anywhere prints "NaN", "undefined", "Infinity" or "$0" for "not in this program". Tasks 2, 7
   and 8 test it.
4. **Phones and reduced motion together:** at 320 and 390 with reduced motion the story shows each step's end state
   at once, every pile stays separate dots, and nothing scrolls sideways. Task 13 tests the layouts at 320, 390 and
   1440; the checkpoint's e2e runs the widths.
5. **Scripts off, or the data asset failing to load:** the home page still shows the hero, every step's text and
   numbers, the static bar and the shaded states map; a hospital page shows its record, net, program dollars and
   headline; a failed fetch shows one quiet "Couldn't load the chart data. Reload to try again." line, never an empty
   frame. Tasks 7 and 12 test it.

### Task 1: Cross-program dollars and peers in the engine

**Files:**
- Create: `engine/js/dollars/whatif.js`, `engine/js/peers.js`
- Modify: `sites/hacrp/web/constants.js` (`BED_BANDS` re-exports `BED_BAND_EDGES`), `sites/hacrp/web/compare.js` (use `bedBand` from the engine if it duplicates it)
- Test: `engine/js/test/dollars-whatif.test.js`, `engine/js/test/peers.test.js`

**Interfaces:**
- Produces: `HAC_RATE = 0.01`; `roundHalfEven(x: number) -> number` (Python's `round`, ties to even, never `-0`);
  `programDollars(row, scenario = null) -> { hrrp, hvbp, hac, net, after, atStake }` where `row` is an estimated
  dollar row (`base, total, hrrpFactor, vbpFactor, cut, hrrp, hvbp, hac, net, after, atStake`) and `scenario` is
  `{ hrrpFactor?, vbpFactor?, cut? }` (a missing key keeps the actual); `netShare(net, total) -> number` (a fraction;
  throws `RangeError` unless `total > 0`).
- Produces: `BED_BAND_EDGES = [100, 300, 500]` (frozen); `bedBand(beds) -> 0|1|2|3|null`; `PEER_MODES = ['state',
  'size', 'teach']`; `peerKey(h, mode) -> string|null` (`h.state`; `'b' + band`; `h.teach` of `'major'|'minor'|'none'`;
  null when the attribute is missing); `median(values: number[]) -> number|null` (null for none; mean of the middle two).

Rule for `programDollars` (mirrors `engine/py/pp_engine/dollars.py` `_chain`): a program whose scenario value equals
the row's (factor within 1e-9, `cut` identical) keeps the row's dollars; a changed factor gives
`roundHalfEven(base × (factor − 1))`; `after = total + hrrp + hvbp`; `atStake` is the row's when neither factor
changed, else `roundHalfEven(HAC_RATE × after)`; `hac = cut ? −atStake : 0` (a plain 0); `net = hrrp + hvbp + hac`.
